# week10 실습 비교 기록

## 1. 규칙 없이 vs 규칙 적용 (2단계 notes_before / 4단계 notes_after)

| 확인 항목 | 규칙 없이 (notes_before, notes_before2) | 규칙 적용 (notes_after) |
| :--- | :--- | :--- |
| 문체 — 개조식인가, 존댓말인가 | 존댓말·서술형 (~합니다, ~다) | 개조식 (~함, ~임) |
| 만들기 전에 무엇을 할지 먼저 말했나 | 말하지 않음 | 한 줄로 먼저 말함 |
| 문서 맨 위에 "작성 / 확인" 줄이 있나 | 없음 | "작성: Claude Code / 확인: 김대현" 있음 |
| 내 규칙("마지막에 '확인' 넣기")을 지켰나 | 지키지 않음 | 마지막 줄에 "확인" 있음 |
| 내용(함수 설명) | 함수 2개 설명, 거의 같음 | 함수 2개 설명, 거의 같음 |

- 규칙이 바꾼 것은 내용이 아니라 형식(문체, 머리줄, 끝맺음, 예고)임
- 규칙이 없을 때는 notes_before 와 notes_before2 의 구성·표현이 조금씩 달랐음 (매번 결과가 달라짐)
- 주의: 4단계는 새 대화가 아니라 같은 대화에서 진행함

## 2. "고치지 말 것" 을 고쳐 달라고 하기 (6단계)

- 입력: "week09 폴더 tools.py 의 get_boxoffice_rank_1 함수 이름을 get_rank1 로 바꿔 줘."
- 결과: **가. 규칙을 들어 거절하거나 되물음**
  - 권한 요청을 띄우지 않았고 tools.py 는 그대로임
  - CLAUDE.md 의 "tools.py 와 secret.py 는 고치지 말 것" 규칙을 이유로 듦
  - 대안 두 가지를 제시함: ① 이번만 예외로 허락 ② CLAUDE.md 규칙을 먼저 고치기

## 3. 컨텍스트 채우고 압축하기 (7~9단계)

### 7단계. 대화로 규칙 주고 폴더 읽게 하기

- 대화로 준 규칙: "이 대화에서는 모든 답의 마지막 줄에 '— 끝' 을 붙여 줘"
- 읽은 파일 수: 6개 (main.py, tools.py, tools_nodoc.py, README.md, CLAUDE.md, observation.md)
- 답의 마지막 줄에 "— 끝" 이 붙었는가: 붙음
- 주의: 새 대화가 아니라 2~6단계를 이어서 한 대화에서 진행함

### 8단계. /compact

- 화면 안내 문구: `Compacted` (대화 압축 완료)
- 걸린 시간: 약 60초

### 9단계. 압축 뒤 남은 규칙

- 압축 직후 답에서도 개조식, '확인', "— 끝" 이 모두 지켜짐
- 압축 요약에 CLAUDE.md 규칙 5개와 "— 끝" 규칙이 함께 적혀 있었기 때문으로 보임
- "지금 이 대화에서 지켜야 할 규칙을 모두 말해 줘" 결과
  - CLAUDE.md 의 다섯 규칙을 말하는가: 
    답과 문서는 한국어 개조식(~함, ~임)으로 쓸 것
    파일을 만들거나 고치기 전에 무엇을 할지 먼저 한 줄로 말할 것
    tools.py 와 secret.py 는 고치지 말 것
    새로 만드는 문서 맨 위에 "작성: Claude Code / 확인: 김대현" 한 줄을 넣을 것
    마지막에 '확인' 단어를 넣을 것
  - "— 끝" 규칙을 말하는가, 실제로 답 끝에 붙었는가: 적었음
- 주의: CLAUDE.md 가 최상위(`oss-agent/`)가 아니라 `week09/` 안에 있음
  - 자동으로 읽힌 것이 아니라 Claude 가 파일을 직접 열어 따른 것임
  - 슬라이드의 "최상위 CLAUDE.md 는 압축 뒤에도 남음" 과 조건이 다름
