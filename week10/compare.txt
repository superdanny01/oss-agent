작성: Claude Code / 확인: 김대현

[week10 실습 비교 기록]

■ 1. 규칙 없이 vs 규칙 적용 (notes_before / notes_before2 / notes_after)

| 항목              | notes_before / notes_before2   | notes_after (CLAUDE.md 적용)          |
|-------------------|--------------------------------|---------------------------------------|
| 문체              | 존댓말·서술형 (~합니다, ~다)   | 개조식 (~함, ~임)                     |
| 맨 위 작성자 줄   | 없음                           | "작성: Claude Code / 확인: 김대현" 있음 |
| 마지막 '확인'     | 없음                           | 있음                                  |
| 만들기 전 예고    | 없음                           | 무엇을 할지 한 줄로 먼저 말함         |
| 내용(함수 설명)   | 거의 같음                      | 거의 같음                             |

- 규칙이 바꾼 것은 내용이 아니라 형식(문체, 머리줄, 끝맺음)임
- notes_before 와 notes_before2 는 규칙이 없어서 구성·표현이 조금씩 다름 (매번 결과가 달라짐)

■ 6단계. 규칙 어기도록 요청 (tools.py 함수 이름 변경)
- 요청: get_boxoffice_rank_1 → get_rank1 로 이름 바꾸기
- 결과: 거절함 (파일 수정 없음)
- 이유로 CLAUDE.md 의 "tools.py 와 secret.py 는 고치지 말 것" 규칙을 직접 언급함
- 대안 두 가지를 제시함: ① 이번만 예외로 허락 ② CLAUDE.md 규칙을 먼저 고치기

■ 7단계. 대화로만 준 규칙
- 규칙: "이 대화에서는 모든 답의 마지막 줄에 '— 끝' 을 붙여 줘"
- 결과: 이후 모든 답 마지막 줄에 "— 끝" 을 붙임
- 주의: 새 대화가 아니라 2~6단계를 이어서 한 대화에서 진행함

■ 8단계. /compact
- 화면 안내 문구: "Compacted" (대화 압축 완료)
- 걸린 시간: 약 60초  ← 직접 적을 것

■ 9단계. 압축 뒤 남은 규칙
- 압축 직후 답에서도 개조식, '확인', "— 끝" 이 모두 지켜짐
- 압축 요약에 CLAUDE.md 규칙 5개와 "— 끝" 규칙이 함께 적혀 있었기 때문으로 보임
- 주의: CLAUDE.md 가 최상위(oss-agent/)가 아니라 week09/ 안에 있음
  - 자동으로 읽힌 것이 아니라 Claude 가 파일을 직접 열어 따른 것임
  - 슬라이드의 "최상위 CLAUDE.md 는 압축 뒤에도 남음" 과 조건이 다름
- "지금 이 대화에서 지켜야 할 규칙을 모두 말해 줘" 결과: ______  ← 직접 적을 것

■ 10단계. 사용량
- /usage (또는 /cost) 결과: ______  ← 직접 적을 것

■ 느낀 점
- CLAUDE.md 는 강제 장치가 아니라 안내문이지만, 규칙을 적어 두면 형식과 금지 사항이 꾸준히 지켜짐
- 대화로만 준 규칙은 압축 요약에 들어가야만 살아남으므로 오래 지킬 규칙은 CLAUDE.md 에 적는 것이 안전함
